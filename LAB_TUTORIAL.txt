==============================================================================
LAB PROCEDURE - proton/alpha coincidence measurement, two Lynx boxes
IPP Garching rack:  IBIS Prot (proton)  +  S Alpha (alpha)
Repository: https://github.com/joeoak10/lynx-coincidence
==============================================================================
Follow the steps in order. Anyone can repeat this without asking the author.
Lines starting with   >   are typed into Command Prompt (cmd), then Enter.
Text in <angle brackets> = replace with your value.
"STOP" = do not continue until the problem is solved.

THE EXACT HARDWARE (from the photo of the rack)
    IBIS Prot   130.183.43.184   input 1 = PROTON detector   (sync MASTER)
    S Alpha     130.183.43.185   input 1 = ALPHA  detector   (sync SLAVE)
    Do NOT touch the other two boxes:
    IBIS RBS    130.183.43.183   (labelled "Till")
    IBIS ERD    130.183.43.186


THE SCRIPTS (use only these two)
    lynx_measure.py       the real measurement
    lynx_test_sample.py   same thing with test defaults (short, TEST_ label,
                          prints an alpha calibration hint from Am-241)
    (lynx_one_box.py / lynx_two_boxes.py / lynx_coincidence.py are older
     versions kept for reference. Do not use them.)

WHAT YOU GET (data files) - every run makes a new folder
    runs\YYYYMMDD_HHMMSS_<label>\
        events.csv        raw events of both detectors     <-- THE RAW DATA
        coinc_pairs.csv   every proton-alpha pair in the window
        summary.txt       counts, rates, pairs, dt peak, calibration hint
        spectra.png       quick-look plots
        run_meta.json     all settings of the run
    Fake runs get FAKE_ in the folder name automatically. Test runs get TEST_.



==============================================================================
PHASE 1 - HARDWARE (everything powered/bias OFF, supervisor present)
==============================================================================
1.1  Notebook header: date, your name, sample, beam particle, beam energy,
     beam current (from the accelerator operator).

1.2  Write down for IBIS Prot and for S Alpha:
        - serial number on the chassis (this is NOT the IP)
        - IP on the label: 130.183.43.184 (Prot), 130.183.43.185 (Alpha)
        - the Power LED is on (green)
     Check on the rear panel: each box has ONE analog input, and where the
     Ext Sync BNC is. If a box turns out to have two inputs, ask the
     supervisor - this script uses input 1 on each box.

1.3  Write down the detectors: ID / serial of the proton detector and of the
     alpha detector, the preamp used for each.

1.4  Plug in (bias still OFF):
        proton detector -> preamp -> IBIS Prot input 1
        alpha  detector -> preamp -> S Alpha   input 1

1.5  Sync cable: BNC from IBIS Prot "Ext Sync" to S Alpha "Ext Sync".
     First look whether a cable is already there. A loose coax with a BNC
     barrel adapter hangs in front of S Alpha in the photo - ask what it
     belongs to before moving it. Notebook: sync cable connected, time.

1.6  Ethernet from both boxes to the network. Both Power LEDs on.

1.7  Do NOT switch detector bias on yet. The software never does it. The
     supervisor does it in PHASE 6.


==============================================================================

==============================================================================
2.1  Open Command Prompt: Windows key, type  cmd , Enter.

2.2  Check Python and Git:
        > py -3.13 --version
        > git --version
     Python missing -> install Python 3.13 from python.org, tick "Add to
     PATH", open a NEW cmd window.  Git missing -> use 2.3-ZIP.

2.3-GIT  (SDK installed on this PC):
        > cd C:\Lynx\SDK\PythonExamples
        > git clone https://github.com/joeoak10/lynx-coincidence.git
        > cd lynx-coincidence
     The vendor folder is then automatically found one level up
     (C:\Lynx\SDK\PythonExamples\DataTypes).

     SDK NOT installed:
        > cd C:\
        > git clone https://github.com/joeoak10/lynx-coincidence.git
        > cd lynx-coincidence
     and copy the vendor folder DataTypes from the USB stick to C:\DataTypes

2.3-ZIP  (no git, or GitHub unreachable from the lab PC):
     On any PC open https://github.com/joeoak10/lynx-coincidence ->
     green "Code" button -> "Download ZIP" -> put on the USB stick -> unzip on
     the lab PC into C:\Lynx\SDK\PythonExamples (the folder may be called
     lynx-coincidence-main; that is fine), then:
        > cd C:\Lynx\SDK\PythonExamples\lynx-coincidence-main

2.4  Python environment (once per PC):
        > py -3.13 -m venv .venv
        > .venv\Scripts\activate.bat
        > python -m pip install matplotlib
     You must see (.venv) at the start of the line. In every NEW cmd window:
        > cd C:\Lynx\SDK\PythonExamples\lynx-coincidence
        > .venv\Scripts\activate.bat
     (No internet for pip? The script still works without matplotlib - it
     only skips the spectra.png plot.)

2.5  Check:
        > dir
     lynx_measure.py and lynx_test_sample.py must be listed.


==============================================================================
PHASE 3 - FAKE RUN (no hardware; proves code and output files work)
==============================================================================
3.1  > python lynx_measure.py --label demo
3.2  Expected: lines with [fake], a SUMMARY block, and
        "[run] all files in ...\runs\<timestamp>_FAKE_demo"
3.3  > dir runs
     Open the newest folder. events.csv, coinc_pairs.csv, summary.txt,
     run_meta.json (and spectra.png) must exist. If not -> STOP.
3.4  Delete the fake data:
        > rmdir /s /q runs


==============================================================================
PHASE 4 - NETWORK AND CONNECTION CHECK
==============================================================================
4.1  ONE-COMMAND CHECK that both Lynx boxes are connected (changes nothing
     on the instruments, no start, no HV):
        > python lynx_measure.py --check
     It does two things for IBIS Prot and S Alpha:
        STEP 1  ping the IP            "OK - answers ping"  or  "FAIL"
        STEP 2  connect with the vendor library    "OK - connected" or "FAIL"
     Final line:
        RESULT: READY.      -> go on to 4.2
        RESULT: NOT READY.  -> STOP. Fix the first FAIL:
           ping FAIL            Ethernet cable, Power LED on the box, network
                                port, PC network settings, correct IP; ask
                                IPP IT if the PC is not on the Lynx network
           ping OK, connect FAIL  login, box busy/locked by another program
                                (close Genie/other Lynx software), or the
                                vendor-library message printed above
           "vendor DataTypes library is Python 2"  -> STOP, see 4.2 case B
     Manual alternative (same as STEP 1):
        > ping 130.183.43.184
        > ping 130.183.43.185
     "Reply from ..." = OK, "Request timed out" = not connected.

4.2  Read-only probe of both real Lynx boxes (no start, no HV, nothing is
     changed on the instrument):
        > python lynx_measure.py --probe
     CASE A - it prints, for each box, the machine name, the type returned
     by getListData, a timebase, and a few first events with attributes
     (channel and a time stamp). Write the timebase and the attribute names
     in the notebook. Then continue.
     CASE B - it says "vendor DataTypes library is Python 2 ..." -> STOP.
     Real mode cannot work until that library is ported to Python 3 (or the
     vendor Python 2 tools are used). This is the one known blocker; no
     setting in this script can fix it.
     CASE C - "DataTypes folder not found" -> put the vendor folder at
     ..\DataTypes or C:\DataTypes (see 2.3) and repeat.

4.3  Time stamps: if the probe shows the time stamps are NOT in nanoseconds
     (check the timebase), open lynx_measure.py in Notepad and set
        TIMESTAMP_TO_NS = <factor that converts the time stamp to ns>
     (default 1.0). Wrong factor = wrong dt axis and a wrong coincidence
     window. Ask the supervisor if unsure.


==============================================================================
PHASE 5 - SETTINGS IN THE SCRIPT (usually nothing to change)
==============================================================================
Open it:   > notepad lynx_measure.py
Only the CONFIG block at the top matters. Already correct:
        PROTON_IP = "130.183.43.184"     ALPHA_IP = "130.183.43.185"
        INPUT = 1      ENABLE_HV = False  (LEAVE False)
Check / fill:
        LYNX_USER / LYNX_PASSWORD   default administrator / password; change
                                    only if the lab changed the login
        BEAM_PARTICLE, BEAM_ENERGY_KEV, BEAM_CURRENT_NA   from the accelerator
                                    log; they are written into run_meta.json
        COINC_WINDOW_NS = 200_000   software window +-200 us; first value on
                                    purpose wide; tighten after PHASE 7/8
        CAL                         filled after calibration (PHASE 7)
Save the file. Any change you make at the lab: write it in the notebook and
commit it (PHASE 11).

Sync codes: the numbers for external sync (263 / 264) and master/slave (1/0)
are NOT verified against the SDK manual. They are the first thing to doubt
if the two boxes do not agree in time (see PHASE 7 check).


==============================================================================
PHASE 6 - DETECTOR BIAS ON (supervisor)
==============================================================================
6.1  Supervisor switches on bias for both detectors (polarity and voltage
     from the datasheet). Never alone, never from the script (no --hv).
6.2  Notebook: bias voltage and leakage current of each detector, time.
6.3  Wait until the leakage current is stable (a few minutes).


==============================================================================
PHASE 7 - TEST RUN + ENERGY CALIBRATION
==============================================================================
Purpose: prove both boxes record, sync works, and calibrate the alpha
detector BEFORE the real sample.

7.1  Put the Am-241 source in front of the alpha detector (vacuum etc. as
     the lab requires - ask the supervisor).

7.2  Run the test script (real boxes, sync cable connected, 5 minutes):
        > python lynx_test_sample.py --real --sync --label Am241_alpha
     (If you instead test with a sample in the beam, use
        > python lynx_test_sample.py --real --sync --label W_tile_test )

7.3  Read the SUMMARY printed at the end (also saved in summary.txt):
        events total       both detectors must have counts. 0 = bias off,
                           wrong input, detector not connected -> STOP.
        proton / alpha rates   plausible?
        pairs / dt peak    "ratio >> 1" = a real time peak = the two boxes
                           are time-aligned. "ratio ~ 1" = flat = no
                           correlation or the sync does not work.
                           With only an Am-241 source on the alpha detector
                           there is no true coincidence, so a flat dt is
                           expected in that case.
        CALIBRATION HINT   prints  slope = <x> keV/ch  for the Am-241 line
                           (5485.56 keV).

7.4  Calibration: open lynx_measure.py and put the slope in CAL, e.g.
        CAL = {
            "proton": (None, None),
            "alpha": (8.8271, 0.0),     # <- slope keV/ch from the hint
        }
     One point means offset 0. A second known line or a pulser gives a real
     offset. Write slope and offset in the notebook. Save the file.

7.5  Remove the source.


==============================================================================
PHASE 8 - THE MEASUREMENT
==============================================================================
8.1  Beam on the sample (accelerator operator). Notebook: sample, particle,
     energy, current, collected charge, start time.

8.2  Start:
        > python lynx_measure.py --real --sync --preset 1800 --label W1_pos1
     --preset is seconds (1800 = 30 min). For hours:
        > python lynx_measure.py --real --sync --hours 2 --label W1_pos1
     The script prints the running totals every 2 s. Ctrl+C stops early and
     keeps everything collected so far.

8.3  At the end it prints the SUMMARY and "all files in runs\<folder>".

8.4  Check immediately:
        > dir runs
     Open the newest folder; events.csv must have rows; read summary.txt.
        events = 0       -> bias, input, cable. STOP and fix.
        no proton or no alpha events -> that box/detector is not recording.
        pairs = 0        -> window too small, sync problem, or no true
                            coincidences.
        warnings starting with !!! must be understood before you continue.

8.5  Notebook: end time, folder name, events, pairs, anything unusual.
8.6  Next sample or position: change --label and repeat 8.1-8.5.


==============================================================================
PHASE 9 - RE-ANALYSE SAVED DATA (no Lynx needed)
==============================================================================
        > python lynx_measure.py --from-csv runs\<folder>\events.csv --label replot
Makes a new REANALYSIS_ folder with new pairs, summary and plots using the
current COINC_WINDOW_NS and CAL values. Use this after tightening the window
or after setting the calibration. The original data is never changed.


==============================================================================
PHASE 10 - FINISH AND SECURE THE DATA
==============================================================================
10.1 Beam off (operator).  10.2 Bias off (supervisor); notebook: time.
10.3 Copy all data to the USB stick (replace E: with the drive letter):
        > xcopy runs E:\lynx_runs /E /I
     Also send a copy somewhere else (email / network share). Open a file
     from the copy to check it works. The runs folder is NOT on GitHub.
10.4 Unplug detectors/sync cable only after the bias is off.
10.5 If you changed lynx_measure.py at the lab (calibration, timestamp
     factor, login): see PHASE 11B.


==============================================================================
PHASE 11 - GITHUB  (https://github.com/joeoak10/lynx-coincidence)
==============================================================================
11A  Upload / update the code from your home PC
     You need git installed (git-scm.com) and a GitHub login for joeoak10.

     First time on this PC:
        > cd C:\Users\<you>\Documents
        > git clone https://github.com/joeoak10/lynx-coincidence.git
        > cd lynx-coincidence
     Copy these files into that folder (File Explorer, replace if asked):
        lynx_measure.py   lynx_test_sample.py   LAB_TUTORIAL.txt   .gitignore
     (.gitignore starts with a dot; if you cannot see it, enable "Hidden
     items" in Explorer -> View.)
     Then:
        > git status
        > git add lynx_measure.py lynx_test_sample.py LAB_TUTORIAL.txt .gitignore
        > git commit -m "Final measurement scripts and lab tutorial"
        > git pull
        > git push
     The first push opens a browser window to sign in to GitHub. If it asks
     for a password in the console instead, use a Personal Access Token:
     GitHub -> Settings -> Developer settings -> Personal access tokens.
     If you get "rejected" or "non-fast-forward": run  git pull  and then
        git push  again.
     If the default branch is called master, git push still works; check
     with  git branch .

     Optional - remove the old superseded scripts from the repo:
        > git rm lynx_one_box.py lynx_two_boxes.py acq_listmode__1_.py
        > git commit -m "Remove superseded scripts"
        > git push
     (Check the exact file names with  dir  first. Skip this if unsure.)

     No git on the home PC? Use the website: open the repo -> "Add file" ->
     "Upload files" -> drag the four files in -> "Commit changes".

11B  Save changes made at the lab PC
        > git status
        > git add lynx_measure.py
        > git commit -m "Lab changes <date>: calibration / settings"
        > git push
     No GitHub login on the lab PC? Copy lynx_measure.py to the USB stick and
     commit it at home. Never leave a change only on the lab PC.

11C  Next lab visit, get the latest code:
        > cd C:\Lynx\SDK\PythonExamples\lynx-coincidence
        > git pull


==============================================================================
TROUBLESHOOTING
==============================================================================
python not recognized           use  py -3.13  or install Python / PATH
Python 2 / SyntaxError          vendor DataTypes is Python 2 (PHASE 4, case B)
DataTypes folder not found      put it at ..\DataTypes or C:\DataTypes
--check says NOT READY          read the first FAIL line (PHASE 4.1)
ping times out                  cable, port, PC network settings, IT
"real run needs --sync"         add --sync (cable connected) or --no-sync
could not set external sync     sync codes unverified - check SDK manual
events = 0                      bias off, wrong input, detector not connected
no events with a time stamp     run --probe; the real event format differs
pairs = 0                       window too small, no sync, no true coincidence
dt peak ratio ~ 1               not time-aligned: sync cable / --sync / codes
folder already exists           two runs in the same second; run again
git push rejected               git pull, then git push
